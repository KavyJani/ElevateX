# API routes and permission model

API base: `/api/v1`. Swagger UI: `/api/docs` on the API listener. Health: `GET /api/v1/health` (no authentication). Configure `ELEVATEX_DATABASE_URL` with an external PostgreSQL service; without it, persistent database routes report HTTP 503. See the root README for migration and one-time admin bootstrap commands.

| Route group                                            | Access rules and behavior                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| ------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `/auth/*`                                              | Public signup accepts investor/founder only; email verify/login/reset are throttled. Accounts must verify their email. Roles come from server-owned profiles. Mutations require CSRF; sessions use opaque hashed tokens and secure cookies.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| `/onboarding/:role/*`                                  | Static step catalog is public; applicant drafts and step writes require a verified session of the matching role. The API enforces step sequence and required fields. Previously submitted applications cannot be reopened or duplicated.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| `/investor-applications/*`, `/founder-applications/*`  | Owner-scoped draft/status reads and submission; submit is idempotency-protected by state and server validation. Admin transitions are separate.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| `/admin/applications/*`                                | ADMIN only; applicant list and review decisions. Approval/rejection/information-request transitions are stored in history and audit; rejection or request-information needs a reason; actor cannot review their own submission.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| `/admin/documents/*`, `/documents/*`                   | ADMIN-only review list/actions. Applicant files are owner-only unless an approved document has an explicit per-investor grant; accepted connection alone does not disclose bytes. Admin read access creates an audit event. Short-lived storage links are returned only after server authorization.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| `/startups`, `/startups/:slug`, `/startups/stats`      | Public, approved-only field projection. Demo records carry explicit demo labeling and do not inflate live platform counts. Query filter/facets/sorting/page are validated and bounded.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| `/admin/startups/*`, `/admin/users/*`                  | ADMIN-only listing publication and reversible account suspension. Listing publication requires a separately approved founder application, explicit consent and a nonempty dedicated public summary. User role changes are not provided; suspension revokes sessions and is audited.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| `/connections/interests`, `/connections`, `/watchlist` | Investor interest/watchlist actions require a real, non-demo approved startup. Founder decisions require startup ownership; duplicate pending/accepted interest is rejected. An accepted request creates an accepted connection.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| `/conversations/*`, `/meetings/*`                      | Conversation/messaging and meeting routes require an accepted connection and participant membership on every request. Meeting times are future-bounded and timezone validated. Notifications are owner-scoped.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| `/documents`                                           | Authenticated, server-validated private uploads and owner-indexed files. Cloud storage credentials are required for bytes; local unsupported operations fail without claiming upload success.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| `/users/*`                                             | Authenticated minimal settings/overview; sensitive settings are owner-scoped.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| `/financial-records`                                   | Founder-only, owner-startup monthly records; categories include revenue, expenses, gross/net profit or loss, cash balance/flows, customer count, ARPC, churn, hiring/marketing costs and funding. History is private, USD-only, capped to the latest 36 months for forecasts and treated as owner-entered rather than independently verified.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| `/forecast`                                            | `POST` creates a founder-owned, versioned v2 scenario snapshot using up to 36 owner-entered financial-record periods plus validated assumptions. The deterministic engine calculates conservative/base/optimistic gross profit, P&L, cash flow, monthly burn, break-even/runway and a separate starting-revenue downside sensitivity; it does not calculate valuation. `GET /forecast/scenarios` lists the founder’s versions; `GET /forecast/shared` lists versions explicitly shared with the signed-in investor; `GET /forecast/scenarios/:id` permits only the founder owner or that active investor’s READ share. `POST /forecast/scenarios/:id/share` requires a verified active investor and accepted connection; `DELETE /forecast/scenarios/:id/share/:userId` revokes only the founder’s own grant. Inputs/results are not investment advice or a valuation guarantee. |
| `/forecast-shares`                                     | `POST /forecast-shares/:scenarioId` grants explicit READ access to a verified active investor only when the founder owns the version and an accepted founder–investor connection exists; `DELETE /forecast-shares/:scenarioId/:userId` revokes that founder’s grant. Grant/revoke and forecast access are separately validated and audited; this permission does not grant access to documents. Nested scenario share routes are retained as equivalent aliases.                                                                                                                                                                                                                                                                                                                                                                                                                 |
| `/ai/*`                                                | Contextual onboarding help is available statically. Generated AI requires the configured server-side LLM service. Persistent conversations/messages are isolated to the signed-in user when PostgreSQL is configured. AI is advisory; admin decisions remain human-only. Usage accounting/quotas and streaming remain incomplete.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| `/contact`                                             | Rate-limited public contact submission; only confirms receipt when the configured email service accepts the message. CSRF applies to mutations.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |

No API executes trades, transfers funds, custodies assets, or grants admin through public registration. No test is authorized to mutate a shared production database.

### Investor approval gate

Email or identity verification is not the same as admin approval of an investor application. The investor's latest application must have status `APPROVED` before the server accepts a new investor interest request, accepts an interest request into a connection, grants the investor access to a shared forecast, or serves shared forecast lists/details. A missing, pending, rejected, or information-requested application is denied. Read-only profile discovery is not an approval signal; explicit forecast grants remain separate from document permissions.
